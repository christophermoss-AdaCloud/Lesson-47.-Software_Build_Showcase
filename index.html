Lesson 47: Software Build Showcase

Interactive 60-minute micro site for Sixth-form Computer Science students.

Lesson Structure (60 Minutes)

1) Do Now / Starter (5–7 mins)

Image critique on entry using sticky notes.
  • Write three things wrong with the app design shown.
  • Prompt: “If you were the developer, what user requirements did they ignore?”
  • Purpose: immediate settling task + UX-focused requirement analysis.

2) Hook & Context (5 mins)

  • Reveal challenge: create an inventive software design showcase.
  • Class vote decides winner.
  • Prize + chance to present to BlueShift Education in assembly on Tuesday 2nd June 2026.
  • Rubric reminder: clear problem definition + proposed solution.

3) Main Activity: “The BlueShift Pitch” (25 mins)

  • Create a pitch in one medium: poster, role-play pitch, paper prototype, or storyboard.
  • Prepare a short defense of design choices.

4) Showcase & Peer Assessment (15 mins)

  • Gallery walk or rapid-fire elevator pitches.
  • Each student receives three voting tokens.
  • Votes based on Clarity, Detail, and Innovation.

5) Plenary & Winner Announcement (8 mins)

  • Announce winner and award prize.
  • Winner explains one key design constraint and how it was overcome.
  • Exit ticket: one refinement based on peer feedback.

Differentiation & Criteria Support

Level 1 Scaffold

  • Use a Design Pitch Template with sentence starters.
  • Prompt structure: purpose → users → user requirements → solution outline.
  • Chunk work into short checkpoints every 5 minutes.

Level 2 Pass Checklist

  • Explicit problem definition statement.
  • Clear proposed solution.
  • Pre-defined functions/subroutines list.
  • At least two test plan ideas.

Merit / Distinction Extension

  • Add wireframes/flowcharts to compare alternatives (Merit).
  • Defend choices using constraints: time, technical feasibility, user needs, maintainability (Distinction).
  • Justify why chosen feature was better than one alternative.

    Teacher Notes for Observation Panel

    Assessment for Learning (AfL) Continuous AfL is built into the Do Now, teacher questioning during prep, and peer voting during showcases.
    Inclusivity Choice of output format (visual, verbal, physical) supports different learner profiles. Templates prevent lower-mark students from feeling overwhelmed.
    Engagement The BlueShift audience and competitive voting increase authentic motivation and improve quality of justification.

    Quick Answers to Key Teacher Questions

    What prize could we give?

    • BlueShift mentoring slot or branded tech item.
    • Raspberry Pi / micro:bit starter kit.
    • Coding platform voucher (e.g., Udemy/Codecademy).
    • Developer accessories (wireframing notebook, desk kit).

    How to support lower-mark students?

    • Sentence-starter template and model example.
    • Checklist with must-include Pass points.
    • Guided teacher prompts: “Who is the user?” “What problem is solved?”
    • Pair support and mini-deadlines.

    What meets Distinction justification?

    • Clear comparison against at least one alternative.
    • Reasoning linked to constraints and user needs.
    • Technical feasibility and testing implications.
    • Evidence from wireframe/flowchart or prototype choices.
